# 规则：漏斗一致性（Funnel Consistency）

> 来源：2026-10-31 商业模式复盘——站点从"工程师叙事"（软件工程底座）
> 转向"业务叙事"（把 Demo 变成能收尾款的系统）后，一度出现 #fde 与
> #partner 两个板块讲同一件事、标题仍是同行黑话（AI FDE）、板块尾部
> 残留旧关键词堆叠。每次加新东西都很快，删旧东西很慢——需要一把规尺。

## 铁律（Iron Law）

**任何新板块 / 新文案 / 新产品位，动手前先回答一个问题：**

> 它落在漏斗哪一环？

| 环 | 站上对应 | 唯一载体 |
|---|---|---|
| 获客筛人 | #workshop 工作坊 | 低票申请制小班 |
| 成交 | #phone + #download + #fit | AI 手机 + 免费底座下载 |
| 留客续费 | #products + #case | 底座/工作台 + 落地版图 |
| 放大 | #partner 代理 | 行业主理人模式 |

回答不出来 → 不做。同环已有载体 → 并入不新增。

## 执行口径

1. **一环一载体**：合作路径只讲一条（培训→陪跑→独立），不许两个板块
   各讲一遍；新想法先找旧载体，改旧优于建新。
2. **命名过业务语**：对外文案禁用内部黑话（FDE、DAG、工作流引擎）；
   检查法：把标题念给目标客户听，他复述不出来就重写。
   标题改动必须同步 `<title>` / meta description / og:* 三件套。
3. **CTA 双轨制**：企业客户与行业伙伴永远是两个独立入口，
   mailto 用 `?subject=` 区分来源（企业定制咨询 / 代理合作申请 /
   工作坊报名-企业老板 / 工作坊报名-伙伴认证 / 工作台陪跑申请）。
4. **定期扫旧**：每次新增板块后，通读一遍整页 nav 与 section 顺序，
   删除与旧载体重复的内容；关键词堆叠、无名列表是优先清除对象。
