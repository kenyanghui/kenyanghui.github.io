# 复盘：Loong 宣传内容两轮重写（2026-11-04）

> 背景：官网（www.aibay.asia）Loong 产品位长期是「工程师写给工程师」的
> 内部视角。本轮按 owner 定调「优势=workflow、矩阵兵法、资源优化、
> 专为技能与专家能力优化、专为手机优化」做两轮重写并上线（8e287a4 →
> d32b151）。本文沉淀可复用的改写方法论与验证坑，供下次宣传迭代直接套用。

## 一、改写方法论：内部视角 → 买方语言

第一轮重写最大的产出不是文案本身，是确认了「翻译」这个动作有固定范式：

| 内部黑话（旧） | 买方语言（新） | 翻译规则 |
|---|---|---|
| 34 条工程铁律 / 证据链验收 | 「不撒谎的技术团队」「做完的每一步都有证据」 | 机制数量不露，机制翻译成承诺 |
| Skill 与工作流开发流水线 | 「干得好的活沉淀成技能，下次一句话复用」 | 把「我们怎么造」改成「你得到什么」 |
| map/pipeline/race 满编扇出 | 分进合击 / 流水接力 / 赛马破难 / 量体裁衣 | 英文术语 → 兵法汉语，先讲打法再讲原理 |
| 命令行/IDE 双形态、私有化部署 | 「装好即用、自动更新」 | 部署形态是卖点还是买方决策项，先想再写 |

**规则候选：新板块动笔前先做一次黑话清点**——把旧文案里数量词（N 条铁律）、
英文术语（map/reducer）、内部代号逐个列出，问「买方拿这条做什么决策」；
答不上来的删掉，答得上的翻译成承诺句式。

## 二、能力宣传的诚实性边界

手机联动 Desktop（扫码配对/PWA）当时状态是**调研完成、未实装**
（报告 /data/matrix-reports/2026-11-02-mobile-research/report.md）。
处理方式：文案落在既成事实上——「底座专为手机优化：技能与工作流长在
手机里」（手机预装工作流是真实现状），未写「手机远程操控电脑」。

**规则候选：宣传句逐条对应「已交付 / 调研中 / 规划中」三档标注**，写进
文案草稿的评审清单；未实装能力只能用「规划中」措辞或干脆不写。这与
loong-workflow「无证据不放过」同源：宣传位也是一种完成断言。

## 三、验证坑（本轮实测，补进 verify-before-live 的候选条文）

1. **懒加载假破图**：Playwright `networkidle` 后统计
   `!i.complete || i.naturalWidth===0`，会把所有 `loading=lazy` 且尚未
   进入视口的图误报为破图（5 张全误报）。正确做法：先逐张
   `scrollIntoView()` + 短等待，再统计；否则「零破图」断言不可信。
2. **公网回环 000 ≠ 链接坏**：本机 curl 公网 IP（106.53.176.184:8001）
   超时返回 000，同一 URL 本机 127.0.0.1 复验 206/200。验证脚本要区分
   「链路不通」与「资源不存在」：出网方向超时的环境，公网直链改打
   本机回环地址复验，别把 000 当 badlink 修链接。
3. **000 与 200 并存时先信本机**：本机 nginx 是同一配置的权威实例，
   回环 200 即资源在；公网可达性另行抽测（线上真实用户路径）。

## 四、最低成本扩版：复用现有 CSS 类

「算力矩阵·兵法」板块四个卡片直接复用 `.gates-visual/.gatev` 类与
`.section-head`（内联 margin-top 变奏），零新增 CSS、零改 main.js
（reveal 选择器已覆盖 `.gatev`）。代价是语义上「五道门」与「兵法」共用
样式；换来的好处是：改版不动样式表 → 不触发 CSS 配平检查 → 验证面最小。

**规则候选：新板块优先扫描现有 section 的 DOM 模式做「样式克隆」**，
只有当现有类表达不了信息结构时才新增 CSS；新增 CSS 必须同步把新卡片
类追加进 js/main.js 的 reveal 选择器（这条 verify-before-live 已有，
本轮实证它抓不到「零新 CSS」路径——反向也成立：零新 CSS 就零遗漏风险）。

## 五、流程经验

- **版本号与下载源的一致性**：下载区版本（v0.35.2）落后实际发行
  （v0.35.3）一版才发现；站上版本号应从 latest.yml 之类的机器可读源
  生成，而不是手抄。update_downloads.py 对齐 desktop-beta 更新源是
  遗留 TODO。
- **远端有新提交是常态**：push 被拒后 `git pull --rebase` 重推即可
  （本轮撞上微信域名校验文件 6a95452）；与 verify-before-live 的
  「443 超时退避重试」并列，构成「push 失败的两类常见形态」。
- **SSOT 双写纪律**：website-workflow 独立仓是权威源，本站
  workflows/website/ 是随站快照；复盘先提交独立仓，再 subtree 或手动
  同步回站内快照（见 86e7a7c：subtree 不可用时的替代做法）。
